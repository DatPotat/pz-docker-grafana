# Project Zomboid b42.20 MP + мониторинг

Docker Compose стек: выделенный сервер Project Zomboid build 42 с готовыми метриками, логами, бэкапами и ежедневным перезапуском по расписанию.

Разворачивается одной командой, настраивается одним файлом `.env` (кроме непосредственно игровых настроек).

## Что внутри

| Сервис | Роль |
|---|---|
| `zomboid` | Сам сервер, ставится через SteamCMD |
| `rcon-exporter` | Онлайн игроков по RCON, события из лога сервера |
| `scheduler` | Ежедневное обслуживание: сохранение, бэкап, перезапуск |
| `prometheus` | Хранение метрик, 30 дней |
| `loki` + `alloy` | Хранение и сбор логов, 30 дней |
| `grafana` | Дашборд |
| `node-exporter` | Метрики хоста: CPU, память, диск, load |

## Требования

- Ubuntu-сервер с Docker и Docker Compose
- Память настраивается `PZ_JVM_XMS` и `PZ_JVM_XMX` в `.env` (минимум 6g)
- Свободное место: сервер и моды занимают несколько ГБ, плюс мир и бэкапы

## Быстрый старт

**1. Настройки**

```bash
cp .env.example .env
```

Заполните в `.env` три пароля: `PZ_ADMIN_PASSWORD`, `PZ_RCON_PASSWORD`, `GF_SECURITY_ADMIN_PASSWORD`. Пустые значения не подменяются дефолтами - сервер не запустится, и это сделано намеренно.

**2. Сертификат для Grafana**
Требуется для безопасного доступа в панель по `https`.
```bash
mkdir -p grafana/certs
IP=<ip-вашего-сервера>
openssl req -x509 -nodes -newkey rsa:2048 -days 3650 \
  -keyout grafana/certs/grafana.key \
  -out grafana/certs/grafana.crt \
  -subj "/CN=${IP}" \
  -addext "subjectAltName=IP:${IP},DNS:localhost,IP:127.0.0.1"

sudo chown -R 472:0 grafana/certs
sudo chmod 640 grafana/certs/grafana.key
```

Права `472:0` обязательны - под этим UID работает контейнер Grafana.

**3. Запуск**

```bash
docker compose up -d --build
```

Первый старт занимает время: SteamCMD скачивает сервер, затем сервер тянет моды из мастерской. Прогресс: `du -sh server/`.

**4. Порты**

```bash
sudo ufw allow 16261/udp
sudo ufw allow 16262/udp
sudo ufw allow 3000/tcp
```

**5. Доступ**

Grafana: `https://<ip>:3000`. Сертификат самоподписанный, браузер предупредит при первом заходе.

**6. Права на файлы**

```bash
sudo apt install -y acl
make fix-perms
```

Контейнеры работают от root, без этой команды каталоги `data/`, `server/` и `backups/` не будут доступны вашему пользователю на запись.

## Как это работает

### Настройка сервера

Конфигурация PZ создаётся **один раз** при первом запуске - минимальный `.ini` из значений `.env`, всё остальное берёт игровые умолчания. Дальше файл ваш: правьте `data/Zomboid/Server/<имя>.ini` напрямую или готовьте его локально и копируйте на сервер. Стек его больше не трогает, поэтому список модов и песочница не затираются при обновлениях.

Обратная сторона: изменения в `.env` после первого запуска в конфиг **не попадают**. Пароль RCON, порты и лимит игроков придётся править в обоих местах.

### Метрики

Онлайн игроков берётся через RCON. События сервера - ошибки, смерти, подключения, сохранения, нехватка памяти - вычитываются из `server-console.txt` регулярными выражениями. Метрики хоста даёт node-exporter.

Шаблоны разбора привязаны к формулировкам консоли b42 и могут перестать совпадать после обновления игры. Если счётчик замер - начинать проверку стоит отсюда.

### Логи

Alloy читает только `server-console.txt` и складывает в Loki. Доступ к docker-сокету ему сознательно не выдаётся: логи остальных контейнеров смотрите через `docker compose logs`.

### Обслуживание и бэкапы

Раз в сутки в указанное время планировщик:

1. Предупреждает игроков за 10, 5 и 1 минуту
2. Сохраняет мир
3. Складывает архив в `backups/` - мир, игроки **и конфиг сервера**
4. Удаляет архивы старше `BACKUP_KEEP_DAYS`
5. Отправляет `quit`

Перезапуск обеспечивает политика `restart: unless-stopped`: процесс завершился, Docker поднял контейнер заново. Отдельного планировщика на хосте не требуется.

Каждый шаг независим: упавший бэкап не отменяет перезапуск, неудачное сохранение не отменяет бэкап.

Параллельно работают встроенные бэкапы самой игры - они настраиваются в `.ini` и складываются в `data/Zomboid/backups/`. В отличие от кастомных, они не включают конфигурацию сервера.

### Моды

Мастерская Steam всегда отдаёт последнюю версию мода, зафиксировать её нельзя. Когда автор публикует обновление, игрок получает его сразу, а сервер продолжает работать на старых файлах до перезапуска - и подключиться становится невозможно.

Решение - не фиксировать версию, а быстро перезапускаться. Поставьте серверный мод, отслеживающий обновления мастерской: он предупредит игроков и вызовет `quit`, а Docker поднимет контейнер, и сервер заберёт новые версии модов при старте. Рекомендую использовать этот: https://steamcommunity.com/sharedfiles/filedetails/?id=3659447892

Не заменяйте `start-server.sh` скриптами автоперезапуска, которые предлагают авторы таких модов. Они оборачивают сервер в бесконечный цикл: контейнер перестанет завершаться, SteamCMD не будет обновляться, а корректное сохранение мира при остановке окажется под угрозой. Политика перезапуска Docker уже выполняет их работу.

### Безопасность

Наружу открыты только игровые порты и Grafana. RCON привязан к loopback, Prometheus, Loki, Alloy и экспортеры вообще не публикуются - они общаются между собой внутри сети Compose.

Важно понимать: **ufw не управляет портами, которые публикует Docker**. Ограничение доступа обеспечивает префикс `127.0.0.1:` в секции `ports:`, а не правила брандмауэра.

## Команды

```bash
docker compose up -d              # запуск и применение изменений конфигурации
docker compose logs -f zomboid    # консоль сервера
docker compose down               # остановка, 120 секунд на сохранение мира

make fix-perms                    # выдать права на каталоги данных
make wipe-world                   # удалить мир и игроков, сохранив моды и конфиг
make wipe-mods                    # удалить скачанные моды, сохранив мир
```

Восстановление из бэкапа делается вручную:

```bash
docker compose stop zomboid
tar -xzf backups/pz-backup-<дата>.tar.gz -C data/Zomboid
docker compose start zomboid
```

## Ограничения

- Нет метрик JVM: без Java-агента расход памяти не виден, признак нехватки `-Xmx` - только счётчик ошибок OutOfMemory
- Нет алертов: проблемы видны на дашборде, но никто о них не сообщит
- Бэкапы остаются на том же сервере, вынос копий не автоматизирован
- Сетевые метрики не собираются
- Разработка на Windows: `node-exporter` там не отдаёт метрики хоста, остальной стек работает
